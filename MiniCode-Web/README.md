# MiniCode Web

MiniCode Web 是 MiniCode 的本地浏览器工作台。页面由 React + TypeScript + Vite 构建，通过本机 FastAPI 服务调用 `MiniCode-Python-repo` 里的 agent 运行时。

## 运行形态

- 浏览器打开 `http://127.0.0.1:8765`。
- 模型、工具、Git、文件和命令由本机 Python 服务处理。
- 任务在独立子进程中运行，可以真正停止。
- 前端使用 SSE 接收模型、工具、审批和完成事件。
- API Key 保存在 `~/.mini-code/settings.json`，不保存到 `localStorage`。

当前使用 SQLite 保存分页记忆、运行状态和会话历史，本地文件保存原文与附件。默认数据目录为 `D:/MiniCodeData`；项目 Markdown 规则独立维护，数据库支持单向 Markdown 导出。

会话分叉、存储增长、工作树应用与恢复详见[会话分叉与工作树说明](../MiniCode-Python-repo/Docs/Documentation/SESSION_FORK_WORKTREE.md)。

对话首屏默认读取最近 5 轮的提问和最终答复；首屏后异步预取下一页历史及最近一轮的一批工作记录。向上滚动接近顶部时自动补充更早轮次，展开工作过程后接近已读内容末尾时自动续载，每批最多 60 条、约 256 KB。读取失败时提供重试入口；单条长记录先显示预览，可加载完整记录。折叠的过程与工具详情不创建内部组件，进入对话不会预取全部历史。

最近 5 个对话使用内存缓存，按序列化数据计上限为 16 MB，保留已加载内容、展开状态和阅读位置；切换时先显示缓存，再确认服务端运行状态。缓存随页面关闭释放，发送、继续和审批仍以服务端确认的状态为准。旧快照通过只读投影兼容，完整模型历史和分叉快照保留。

## 一次构建，直接使用

确保目录结构为：

```text
MiniCode/
  MiniCode-Python-repo/
  MiniCode-Web/
```

安装并构建前端：

```powershell
cd D:\ai测试项目\MiniCode\MiniCode-Web
npm install
npm run build
```

安装 Web 后端并启动：

```powershell
cd D:\ai测试项目\MiniCode\MiniCode-Python-repo
.\.venv\Scripts\python.exe -m pip install -e ".[web,memory]"
.\.venv\Scripts\python.exe -m minicode.web_api --workspace "D:\ai测试项目\MiniCode\MiniCode-Python-repo" --web-runtime primary --web-ultra-runtime primary
```

然后打开 [http://127.0.0.1:8765](http://127.0.0.1:8765)。后端会自动读取同级 `MiniCode-Web/dist` 生产构建。

也可以在本目录直接运行：

```powershell
.\Start-MiniCode-Web.ps1
```

启动脚本及 Python Web 命令行入口默认开启 **Web 限定试运行**：新提交的 Standard / Deep / Ultra 使用 `primary + durable`，页面默认 Deep；TUI 和 Headless / CI 沿用原配置，启动脚本不修改全局设置或迁移旧任务。页面新对话默认不限额；选择自动沿用系统配置且未设置额度时，每轮兜底 256,000 Token / 600 秒，已有固定截止时间不会自动延长。这是 Runtime 预算，不是进程硬超时，也不是费用上限。试运行任务结束后再发送下一条消息。

Standard 项目任务默认在 Local 当前目录执行，也可选择 Worktree；Standard 会直接修改所选目录，页面会标明修改位置。执行模式与 Local / Worktree 环境独立选择。Deep / Ultra 继续使用临时隔离目录、验证和回写流程。模型、工具审批和已有历史保持原样。

输入区右上角「任务设置」收纳验收契约和「任务预算 · 高级设置」。新对话默认选择「不限额、不限时（默认）」，也可选择「648 万 Token · 大型任务」、自动沿用系统配置或自定义额度，运行时长按分钟填写。预算保存在当前浏览器中，按对话独立记忆，发送后、切换对话和刷新页面均沿用，直到手动修改；新建对话恢复默认不限额。6,480,000 Token 是每轮任务累计输入与输出的上限，运行时长从每轮启动重新计时。失败或停止后可点「按当前预算继续未完成任务」：有已保存的主候选时复用修改，保留历史用量并执行原验收；原目录冲突、未结算用量或不确定写入会明确拒绝自动恢复。继续入口需要新版后端支持。

回退时先等待或停止当前任务、关闭现有 Web 服务。`./Start-MiniCode-Web.ps1 -Runtime legacy` 仅回退 Standard / Deep；`-UltraRuntime legacy` 仅回退 Ultra；全部回退需要同时传入这两个参数。直接启动 Python API 时对应 `--web-runtime legacy --web-ultra-runtime legacy`，省略参数时默认使用新链路。不要另开端口绕过同一数据目录的服务锁。

启动脚本固定使用后端 `.venv`，缺失时明确提示。启动前检查 SQLite 配置和 Web 依赖；可执行 `.venv\Scripts\python.exe -m minicode.web_api --check` 单独检查。

同一用户的数据目录只允许一个 Web 后端运行，正式入口统一为 `8765`。更新前端构建或后端代码后，需要停止旧服务，再通过本脚本启动并刷新页面；不要同时保留 `8765`、`8766` 两套服务。未知 `/api` 路径返回 JSON 错误，不再回退到 HTML 首页。

启动脚本读取本机 MiniCode 设置，显示实际数据库与本地附件路径，并初始化 SQLite。无需后台向量索引进程。

原生 Web 不会自动加载后端目录的 `.env`。在用户设置中配置 `memoryDataRoot`，或给启动脚本传入 `-DataRoot D:/MiniCodeData`；保存的位置调整后需要重启服务。

存储配置、单向导出、备份和恢复命令见 [分页记忆文档](../MiniCode-Python-repo/Docs/Documentation/PAGED_MEMORY.md)。

已有会话可在「检查器 → 上下文 → 当前会话任务记忆」点击「导出 Markdown」，下载当前会话的任务状态、决策和分页记忆预览。没有可导出资料或读取失败时会显示原因，可再次点击重试。导出为查看副本，不包含完整聊天记录、长期记忆文件或附件，也不能作为恢复备份。

聊天标题栏右上角「⋯ → 复制为 Markdown」可复制当前会话所有已保存的用户消息、问题回答和最终回复，包括尚未展开的历史轮次，并保留 Markdown 与文本附件内容。图片保留附件名称，不复制二进制文件；工具过程和内部提示词不包含在内。任务结束后可使用，读取失败时可重试，浏览器拒绝剪贴板权限时可在弹窗中手动复制。复制后的文本可保存为 `.md` 文件，属于聊天查看副本，不是会话恢复备份。

同一菜单提供「导出 PDF（简洁版）」和「导出 PDF（原样版）」。简洁版适合阅读与打印，图片保留文字引用；原样版保留聊天气泡、颜色、表格和代码样式，展开上传图片、回复中的图片、执行截图与文本附件。两种版本都读取完整已保存历史，按 A4 分页，长代码自动换行，PDF 文本可选择和搜索。原样版保持图片长宽比；图片加载失败时显示占位说明，可点击「重试图片」后再保存。预览打开后点击「保存为 PDF」，在浏览器打印窗口中选择「另存为 PDF」；打印时隐藏操作栏，可关闭浏览器页眉页脚以使用文档页码。浏览器拦截弹出窗口时，允许后重试即可。导出不包含侧栏、输入框和内部工具文字过程；这是聊天查看副本，不能用于恢复会话。此功能复用现有历史和图片接口，无需额外 PDF 服务。

## 开发模式

终端 1：

```powershell
cd D:\ai测试项目\MiniCode\MiniCode-Python-repo
minicode-web --workspace "D:\ai测试项目\MiniCode\MiniCode-Python-repo"
```

终端 2：

```powershell
cd D:\ai测试项目\MiniCode\MiniCode-Web
npm run dev
```

开发页面位于 [http://127.0.0.1:5173](http://127.0.0.1:5173)，Vite 会把 `/api` 代理到 `127.0.0.1:8765`。

## 页面能力

- 已完成轮次末尾提供“从此处分叉”，继承所选对话上下文；代码从创建时的当前目录状态开始。Git 项目默认独立 Worktree，子会话仍按原项目归组。
- 新项目任务可选 Local / Worktree；右侧变更面板支持预览并应用回原项目。冲突整次停止，成功后保留未提交改动。归档保留工作树，永久删除会检查未应用成果。
- 首页使用浅色侧栏、四个任务起点和固定输入区，点击建议后会填入任务并聚焦输入框。
- 点击左上角搜索或按 `Ctrl / Cmd + K`，查找项目与对话；`Esc` 关闭搜索。桌面侧栏可收起，并记住显示偏好。
- 文件与检查器默认收起，点击右上角按钮按需打开；输入框上方的项目名和分支分别直达文件、变更。
- 输入区显示当前对话范围与模型；点击模型名打开设置，`Enter` 发送，`Shift + Enter` 换行。
- 输入框旁的“权限模式”可选“默认审批”或“完全访问”。完全访问下，文件修改、命令执行和项目外路径访问无需逐项审批，执行节点继承本轮选择。模式按对话保存在本机浏览器，刷新和继续任务时保留；新对话默认完全访问。运行中显示本轮实际模式，排队任务沿用该模式，结束后可切换；切回默认审批会恢复原有确认和拒绝规则。
- 本对话上下文上限默认 400K，保留 128K、256K、512K、模型上限和自定义选项；已有对话保存的上限继续生效，实际窗口受模型与服务容量约束。1K = 1,000 tokens。
- 输入框开头输入 `/` 可选择命令和技能，支持中英文筛选、上下键、鼠标选择、`Tab` 补全与 `Esc` 关闭。`/context` 打开上下文详情；`/compact` 向当前会话提交一次交接笔记与手动轮换请求，实际结果以原有记忆工具的回执为准。新对话、运行中或有待发送附件时，菜单会说明整理不可用的原因；相关记忆工具不可用时由运行时如实报告。技能仍通过 `/skill 名称` 填入并发送。
- 输入草稿按独立新对话、项目新任务和已有会话分别保存在当前浏览器本机；切换或刷新后可恢复，发送确认成功后才清除。浏览器存储不可用时会明确提示草稿仅保留在当前页面。
- 通过 Windows 系统文件夹选择器打开项目，也保留手动路径输入作为备用。
- 左侧分开展示置顶、项目和独立对话；每个项目可展开多个归属于该项目的对话。
- 对话行的垃圾桶先将对话移入“回收站”，左侧底部可进入统一管理页，也可直接打开 `/#trash`。支持搜索、恢复和二次确认后永久删除；回收站状态持久化到本机，重启后仍保留。恢复会保留项目归属、置顶及本浏览器中的草稿。
- 移入回收站期间保留完整会话及关联数据；永久删除清理会话文件、增量记录、输入历史、会话内检查点和实时运行缓存。项目文件、独立保存的项目/全局记忆及分页记忆存储不在此删除范围内。运行中的任务须先停止；永久删除中途失败会保留待清理记录，可重试删除。
- 顶部“新对话”创建不读取项目文件的独立对话；项目行的加号创建可读写该项目的新对话。
- 尚未发送的新对话可点击输入框上方的项目名称，搜索并选择项目、打开其他项目，或切换为独立对话。已有会话隐藏项目切换入口并保持原有工作区绑定。切换会携带文字和本地附件，并保留目标项目已有草稿；原项目的文件引用不会带入其他项目。
- 输入框左下角“＋”支持添加本地图片、文本、代码和日志，项目对话还可引用项目内的文本文件。每条消息最多 8 个附件；文本单文件 64 KB、合计 128 KB，支持 UTF-8 和 GB18030。PDF、Office 文档和整文件夹暂不支持。附件可预览、移除，随消息和草稿保存，提交失败时保留，不会复制进项目目录。
- 图片支持选择、粘贴和拖拽，接受 PNG、JPEG、WebP、静态 GIF，每张原图最多 8 MB。后端校验真实格式，清除 EXIF 等元数据并将长边缩至最多 2048 像素；点击缩略图可放大。图片保存在数据目录的 `image-attachments/`，草稿、历史、排队消息和分叉仅保存引用，备份或迁移时应连同此目录一起保留。仅在请求模型接口时编码图片，不把 Base64 写入消息或浏览器存储。
- 图片能力按提供商、实际接口地址和模型识别为“支持、不支持、尚未确认”。不支持或未确认时保留草稿并阻止发送图片，可切换模型或移除图片；自定义接口可在设置的“图片输入能力”中按服务商说明确认，设置只作用于当前连接。连接测试不代表视觉能力测试。切换到非视觉模型后，历史图片仍可预览，但后续请求只参考已有文字。
- 图片通过 OpenAI Chat Completions 或 Anthropic Messages 内容块发送，Standard / Deep / Ultra 均保留当前图片引用，图片 token 采用保守估算计入预算，实际用量以服务商回执为准。当前 DeepSeek 官方 `deepseek-flash` 已通过真实识图测试；OCR 与独立视觉模型转述尚未接入。
- 工具保存的截图按执行顺序内联显示在对应工具下方，后续步骤与最终回复接在图片后面。折叠工作过程保留截图及其来源工具，缩略图支持放大和下载；历史过程尚未读取时先显示已保存图片，读取后精确关联来源，不重复展示。分页、刷新或后续命令失败不会隐藏已保存图片；引用旧图时保留原图时间。
- 工具图片副本长期保存，删除项目原图或把聊天移入回收站不会清理副本；永久删除聊天时会一并清理。设置中的“聊天图片存储”显示每条聊天的用量，确认后可只清理图片、保留文字记录、文件名和保存时间。清理前后用量发生变化时会要求重新核对；运行中的任务不能清理图片。分叉聊天的独立副本不受父聊天清理影响。
- 图片组会显示可查看、已清理、不可用和加载失败的数量。已清理、文件缺失、文件损坏分别显示明确提示，并禁用放大和下载；临时读取失败保留重试入口，不会被认定为已删除。
- `run_command.image_paths` 声明截图输出，`display_image` 展示已有图片；`view_image` 才会把实际像素交给模型，支持本地 `path` 或本会话已保存的 `image_id`。模型历史只持有图片引用，发送请求时才编码像素。界面任务的交付应分别说明功能检查和视觉检查，读取或保存图片本身不代表视觉检查通过；接口不支持图片或图片无法读取时，返回“未检查”和原因，继续其他工作，不因此反复重试、停止任务或重启程序。
- `record_task_checks` 将功能检查与视觉检查分别保存为通过、未通过或未检查，并记录具体发现及工具调用依据。功能通过必须关联本次实际完成且成功的检查；视觉结论必须关联已通过模型请求传入像素的 `view_image` 调用，无法仅凭文件名、截图保存或同批读取请求登记通过。依据缺失或过期时，仅将对应类别记为“未检查”并说明原因，保留另一类有效结论，任务可继续执行。结论紧随对应工具步骤简短显示，展开该步骤可查看完整发现和依据；尚未加载来源或未执行检查时，说明保留在记录步骤。没有记录的历史任务不显示占位卡片。模型判断只覆盖所述检查范围，最终回复简要交代实际检查结果和未检查项。
- 内置 Playwright 检查支持静态构建与运行中的服务，场景脚本可执行点击、打开弹窗和滚动，再保存视口或局部截图。命令回传可供 `view_image` 使用的图片 ID；截图保留页面、场景、视口、浏览器与来源版本。未就绪的诊断截图明确标记，检查报告单独列出实际执行的断言，不自动产生视觉通过结论。使用方式见 [浏览器检查说明](../MiniCode-Python-repo/Docs/Documentation/BROWSER_CHECKS.md)。
- 已打开项目的新对话立即切换输入区，Git 状态在后台刷新；切换项目后，历史列表刷新也不会阻塞输入。
- 跨项目选择对话时，会自动切换到它所属的工作区再恢复会话。
- 流式查看 assistant 输出、工具调用、运行状态和权限审批。
- 主 Agent 在有新发现、调整方案或遇到阻碍时，用一两句话解释已知事实、影响与下一步，避免逐次播报工具调用和重复空泛状态；简单问题直接回答。公开文字随模型响应增量显示，内部推理不作为对话正文展示。答复先显示为「草稿 · 待验证」，运行时验收通过后在同一条消息上确认最终结果；失败或中断时保留未确认标记。过程说明、消息标识与验收状态随历史保存，刷新后不会再追加一份答案。未提供文本流的模型仍在完整响应到达时显示内容。
- 答复生成后，在正文下方显示实际确认步骤与该步骤耗时；验收通过但仍在保存记录时明确显示「答复已确认，正在保存记录」，断线时改为同步状态提示。未带格式标记的结论在主 Agent 真正结束时转为待确认答复，与最终回执共用消息标识，避免正文重复。
- 只读问答没有代码返修或注册检查时，不保存无用途的代码返修检查点；没有待核对的最终证据时，不预先重复计算快照。仍核对工作区前后变化、生成最终证据并运行已配置检查。快照计时进入 Worker 指标；硬链接在遍历祖先前提前拒绝，保留最终路径安全检查。
- Standard、Deep、Ultra 执行中使用统一的固定进度区，展示实际模式、执行阶段、耗时、最近进展，以及模型响应、工具执行、审批或断线恢复的等待状态。结束后移除固定进度区；需要补充信息时继续保留提示。实际模式可在本轮工作过程中回看，与输入框“下次发送”设置独立。
- Deep 和 Ultra 的独立任务显示为子 Agent 入口，点击后在右侧查看目标、重试、结果和所属工具调用；详细执行安排可在运行面板查看。只有调度器实际创建独立核验或并行任务时，页面才展示对应流程。
- 独立核验分别显示等待、未开始、复核通过、发现问题、执行中断和报告未被接受；前置任务失败不会被误报成核验不合格。子代理面板解释复核职责及继续方向，历史失败原因只关联同一运行、计划、状态和执行次数。交付验收逐项区分实际检查证据、AI 复核意见、未通过与未验证，可展开查看检查记录及版本；仅有模型意见不会显示为已具备实际检查证据，缺失证据也不会直接标成检查失败。
- 并行工具事件使用执行、节点、尝试和调用标识关联，避免同名工具结果串到其他任务。待确认的操作不会随普通事件窗口一起移除。
- 主对话沿用普通消息与工具样式，不逐条标注“主 Agent”。子 Agent 的任务在首次活动处显示成员名称与状态，点击后打开右侧“子代理”面板，成员列表与独立记录页可相互切换。详情独立滚动，过程可折叠，结果保留可见；续跑任务归到同一成员，实时更新和历史恢复使用同一套归属数据。运行面板展示完整分工，区分本轮生效设置与实际派发情况；团队已启用但没有子任务时在面板内说明。旧记录缺失的归属不作推测，待审批操作通过入口回到主对话处理。Coordinator 可自行只读分析，文件修改交给成员。
- 运行中按 Enter 或发送按钮先排队，队列贴在输入框上方；点击某条消息的“引导”将其发送给正在执行的任务，在原生安全边界处理。每条消息可删除，或通过“…”取回编辑。服务端确认保存后才清空草稿，刷新、切换对话和服务重启后可恢复回执；重启后未确认处理结果的消息显示为暂停。
- 普通任务成功结束后自动处理队列；带预算、任务契约或 Primary 的任务保留排队消息，结束后点击队列上的“继续”或输入框的播放按钮，用当前任务设置和新的本轮预算启动下一条。停止或失败会暂停队列，继续时其余消息一起保留，不清除正在编辑的草稿。
- 父子 Agent 通信按发送方单独显示在各自工作过程中，不与普通工具调用合并；子代理显示“已向父代理发送消息”，主对话显示“已向子代理发送消息”。展开后查看接收方、消息类型、正文和接收状态；发送中、发送失败及结果未确认分别显示。消息成功发出不等于对方已接收，只有已保存的接收记录才显示“已进入上下文”。异步子 Agent 与 Agent Teams 共用这套展示，历史调用与回执可恢复。
- 咨询子任务通过 `submit_consultation` 回传时显示独立的“已向父代理提交咨询报告”，可展开摘要和完整报告；提交成功与最终验收通过分别记录。仅自动返回最终结果、未主动发消息的核验任务保留实际结果，不补造发送消息事件。右侧子代理列表提供进入工作过程、通信与结果的提示与箭头。
- Builder 通过 `submit_builder_candidate` 回传时，在自己的工作过程中显示独立的“已向父代理提交修改”；父代理的 `accept_builder_patch` 独立显示修改接收记录，并区分已应用、应用后检查未通过、未确认和重新生成。查看修改、等待结果、派发咨询使用中文动作标题。已有历史调用与回执同样适用，无需重新运行任务；未保存的通信不补造。
- 连续成功的工具调用默认合并为可展开的一行；失败、未确认结果和正在运行的调用按原始顺序留在工作过程中，与前后说明和重试相邻，不再集中到答复前。错误先给出中文提示，原始输入输出按需展开；待审批操作保持可见。同一执行节点中，失败之后以相同参数再次调用同一工具并成功，才标记“后续已成功”；并行操作、其他节点和归属不明的旧记录不会被误判为恢复。
- 实时与历史轮次使用相同的对话布局，执行中按顺序展示完整阶段说明与操作，工具标题显示动作与目标。结束时自动将整段过程收成“用时…”一行（没有可靠计时的旧记录显示“查看工作过程”），入口提示尚未确认恢复的调用失败次数及未确认结果数，最终回复保持可见；结束后可手动展开过程查看完整上下文，回复可一键复制。
- 完成后只在过程入口显示本轮用时。验证通过的交付以紧凑一行显示实际资源改动与检查数；仅有运行状态回执时显示「运行状态已确认」，不计为代码测试。详细验证记录、运行详情按需展开；未通过或缺少验证的结果继续显示明确提示。“从此处分叉”保留为次要文字操作。
- 阅读旧消息时流式更新不会抢走滚动位置，点击「有新进展 · 回到底部」可继续跟随；加载更早轮次时保留当前阅读位置。
- 任务结束后汇总本轮记录的资源改动与最终验证结果，支持直达工作区变更和运行详情。没有验证记录时明确显示未验证，不把工作区已有改动算成本轮成果。
